# 快递站管理系统 · 设计时操作流程

> 本文档面向**系统管理员（`admin`）与低代码配置人员**，完整记录如何在「云枢模型驱动低代码开发平台」管理中心中，从零配置并上线一套完整的 **「快递站管理系统（`express_station_app`）」**。
>
> **平台访问地址**：`http://localhost:8088/`（默认管理员：`admin` / `123456`）

---

## 一、系统总体设计蓝图

### 1.1 核心能力覆盖

本应用充分利用了低代码平台的模型驱动、字典驱动、状态机、脚本扩展与多租户能力：

| 业务模块 | 英文表名 | 用到的平台低代码特性 |
| :--- | :--- | :--- |
| **货架区位档案** | `exp_shelf` | 唯一约束（按租户隔离）、`Selection` 分区标签、引用内置 `SYS_ENABLE_STATUS` 字典、安全软删 |
| **快递车批次签收** | `exp_inbound_batch` | 自动编码规则（`EXP_BATCH`）、**主子表 `OneToMany` 明细内嵌编辑**、状态流转按钮 |
| **随车包裹明细** | `exp_inbound_detail` | 明细子表（外键 `ManyToOne` 挂接主表，菜单设为停用以保持主导航清爽） |
| **包裹入库与取件** | `exp_parcel` | 自动编码（`EXP_INBOUND`）、字段长度校验（手机号 11 位）、外键关联货架、`related` 自动带出理货员、**Groovy 计算字段（超期保管费自动计费）**、4 个声明式状态机按钮 + 1 个 Groovy 自定义计费脚本按钮 |
| **问题件处理单** | `exp_problem_order` | 自动编码（`EXP_PROBLEM`）、关联包裹、引用内置紧急度/检验结论字典、**`File` 凭证附件上传**、两段式状态审核按钮 |

## 二、准备阶段：配置数据字典与自动编号规则

使用 `admin / 123456` 登录进入 **「管理中心」** 后，先准备好下拉选项库与单据编号规则。

### 2.1 新建快递专属选项字典（「常用选项字典」）

平台已内置 4 组通用字典（`SYS_URGENCY` 紧急程度、`SYS_APPROVAL_STATUS` 审批状态、`SYS_QUALITY_RESULT` 检验结论、`SYS_ENABLE_STATUS` 启用状态）。我们需要补充 2 组快递行业字典：

1. 点击左侧菜单 **「常用选项字典」** → 左侧点击 **「+ 新增分类」**：
   - **字典 1 — 快递品牌**：
     - 字典名称：`快递品牌`
     - 调用编码：`EXP_COMPANY`
     - 保存后，在左侧选中「快递品牌」，点击右侧 **「+ 添加选项」** 依次录入：
       | 存储值 | 展示名称 | 标签颜色 | 排序 |
       | :--- | :--- | :--- | :--- |
       | `SF` | `顺丰速运` | `primary`（蓝） | `10` |
       | `JD` | `京东物流` | `danger`（红） | `20` |
       | `ZTO` | `中通快递` | `info`（灰） | `30` |
       | `YTO` | `圆通速递` | `warning`（橙） | `40` |
       | `STO` | `申通快递` | `success`（绿） | `50` |
       | `EMS` | `中国邮政` | `success`（绿） | `60` |
   - **字典 2 — 快件规格**：
     - 字典名称：`快件规格`
     - 调用编码：`EXP_PARCEL_SIZE`
     - 右侧选项依次录入：`SMALL / 标准小件`、`MEDIUM / 标准中件`、`LARGE / 大件/重货`、`COLD / 生鲜冷链`。

### 2.2 新增自动流水号规则（「自动编号规则」）

点击左侧菜单 **「自动编号规则」** → 点击 **「+ 新增编号规则」**，创建以下 3 条规则（可在列表中点「试生成」预览效果）：

| 规则代号 (`code`) | 规则名称 (`name`) | 固定前缀 (`prefix`) | 日期格式 (`dateFormat`) | 流水位数 (`seqLength`) | 生成示例 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `EXP_INBOUND` | 包裹入库流水号 | `INB-` | `yyyyMMdd` | `4` | `INB-202611250001` |
| `EXP_BATCH` | 快递车签收批次号 | `CAR-` | `yyyyMMdd` | `3` | `CAR-20261125001` |
| `EXP_PROBLEM` | 问题件工单编号 | `WT-` | `yyyyMMdd` | `3` | `WT-20261125001` |

## 四、设计并上线 5 张数据表（「表单与数据表」）

点击左侧菜单 **「表单与数据表」**，逐一通过 **「+ 新建数据表」** 完成模型设计。

> **重要建模顺序提示（防止外键找不到目标表）**：
> 主表 `exp_inbound_batch` 与明细表 `exp_inbound_detail` 相互引用时，须按 **“先建主表骨架 → 再建子表并外键指向主表 → 最后回主表追加 `OneToMany` 子表字段并重新生成页面”** 的三步顺序操作，平台会自动通过参照完整性校验。

### 4.1 货架区位档案 (`exp_shelf`)

1. 基本信息：中文名 `货架区位档案`、英文表名 `exp_shelf`、所属应用选 `快递站管理系统 (express_station_app)`、版本号 `1.0.0`、默认排序 `shelf_code asc`、开启「安全软删」。
2. **字段设计**：
   - `shelf_code` / `货架编码名称` / 单行文本 (`String`) / 勾选 **必填、唯一、主显示**
   - `zone_type` / `所属分区` / 固定下拉选项 (`Selection`) / 选项填写：`A:A区-标准小件柜,B:B区-中件货架,C:C区-大件地堆区,D:D区-生鲜冷链柜`（必填）
   - `capacity` / `容量上限(件)` / 整数 (`Integer`) / 默认值 `120`
   - `manager_name` / `负责理货员` / 单行文本 (`String`) / 勾选 **必填**
   - `status` / `货架状态` / 数据字典下拉 (`Dict`) / 下拉选择 `启用状态 (SYS_ENABLE_STATUS)` / 默认值填 `ENABLED`
3. 点击 **「检查影响并立即启用」** → 回到列表点击该表行的 **「生成页面」**。

### 4.2 快递车批次签收主子表 (`exp_inbound_batch` + `exp_inbound_detail`)

1. **先建主表 v1.0.0 (`exp_inbound_batch`)**：
   - 字段设计：
     - `batch_no` / `签收批次号` / 单行文本 (`String`) / 勾选 **唯一、主显示**；点击该行 **「高级」** → 「自动编号规则」填 `EXP_BATCH`
     - `courier_brand` / `快递品牌` / 数据字典下拉 (`Dict`) / 选 `EXP_COMPANY`（必填）
     - `driver_name` / `派送司机/快递员` / 单行文本 (`String`)（必填）
     - `arrive_time` / `到站时间` / 日期时间 (`DateTime`)
     - `total_count` / `随车件数` / 整数 (`Integer`)
     - `status` / `签收状态` / 固定下拉选项 (`Selection`) / `ARRIVED:待清点,CHECKED:已清点入库` / 默认值填 `ARRIVED`
   - **业务操作与状态流转按钮**：点「+ 新增状态流转按钮」：
     - 动作标识 `finishCheck`、按钮名字 `完成到站清点`、原状态 `ARRIVED`、目标状态 `CHECKED`、拦截提示 `该批次已完成清点！`
   - 点 **「检查影响并立即启用」**。
2. **再建明细子表 (`exp_inbound_detail`)**：
   - 字段设计：
     - `batch_id` / `所属签收批次` / 关联单选 (`ManyToOne`) / 目标数据表填 `exp_inbound_batch`
     - `tracking_no` / `随车运单号` / 单行文本 (`String`) / 勾选 **必填、主显示**
     - `damaged` / `包装破损` / 是/否开关 (`Boolean`)
     - `note` / `验视备注` / 单行文本 (`String`)
   - 点 **「检查影响并立即启用」** → 回到列表对该表点 **「生成页面」**。
3. **回主表升级 v1.0.1 挂载 `OneToMany` 子表页签**：
   - 在列表中找到 `exp_inbound_batch` 点 **「设计/改版」**（版本号自动递增为 `1.0.1`）；
   - 新增字段：`details` / `随车包裹明细` / 关联明细子表 (`OneToMany`) / 明细表填 `exp_inbound_detail`、关联字段填 `batch_id`；
   - 点 **「检查影响并立即启用」** → 回到列表找到 `exp_inbound_batch` 再点一次 **「生成页面」**（表单内会自动包含子表页签）。

### 4.3 包裹入库与取件 (`exp_parcel` — 核心业务表)

1. 基本信息：表名 `exp_parcel`、中文名 `包裹入库与取件`、所属应用 `express_station_app`、开启「安全软删」。
2. **字段设计**：
   - `inbound_no` / `入库流水号` / `String` / 勾选 **唯一、主显示**；点「高级」填编码规则 `EXP_INBOUND`
   - `tracking_no` / `快递运单号` / `String` / 勾选 **必填、唯一**；点「高级」设最小字数 `6`、最大字数 `32`
   - `courier_brand` / `快递品牌` / `Dict` / 下拉选 `EXP_COMPANY` / **必填**
   - `parcel_size` / `快件规格` / `Dict` / 下拉选 `EXP_PARCEL_SIZE`
   - `recipient_name` / `收件人姓名` / `String` / **必填**
   - `recipient_phone` / `收件人手机` / `String` / **必填**；点「高级」设最小字数 `11`、最大字数 `11`
   - `pickup_code` / `取件码` / `String` / **必填**
   - `shelf_id` / `存放货架` / `ManyToOne` / 目标数据表填 `exp_shelf`
   - `shelf_manager` / `货架理货员` / `String` / 点「高级」→「关联自动带出」填 `shelf_id.manager_name`、**取消勾选「保存到数据库列」**
   - `storage_days` / `滞留天数` / `Integer` / 默认值 `0`
   - `overdue_fee` / `超期保管费(元)` / `Double` / 点「高级」→「自动计算公式」填入：
     ```groovy
     int d = ((row.storage_days ?: 0) as int); return d > 3 ? (d - 3) * 1.0d : 0.0d;
     ```
   - `status` / `包裹状态` / `Selection` / 填 `PENDING:待上架,READY:待取件,PICKED:已取走,PROBLEM:异常滞留,RETURNED:已退回`
   - `remark` / `备注说明` / `Text`
3. **业务操作与状态流转按钮**：
   - 状态流转 1：`putOnShelf`（`确认上架待取`）：`PENDING` → `READY`
   - 状态流转 2：`confirmPickup`（`核验取件出库`）：`READY` → `PICKED`
   - 状态流转 3：`markProblem`（`转为异常件`）：`PENDING,READY` → `PROBLEM`
   - 状态流转 4：`returnSender`（`退回寄件人`）：`PROBLEM,READY` → `RETURNED`
   - 自定义脚本按钮：`recalcOverdueFee`（`核算超期费`，类型选 `脚本逻辑 GROOVY_SCRIPT`），脚本内容填：
     ```groovy
     int d = ((row.storage_days ?: 0) as int);
     double fee = d > 3 ? (d - 3) * 1.0d : 0.0d;
     rs.call('update', [id: row.id, version: row.version, values: [overdue_fee: fee]]);
     return JsonRpcServiceResponse.message('取件码 [' + (row.pickup_code ?: row.inbound_no) + '] 滞留 ' + d + ' 天，超期保管费：￥' + fee);
     ```
4. 点 **「检查影响并立即启用」** → 回到列表点 **「生成页面」**。

### 4.4 问题件处理单 (`exp_problem_order`)

1. 基本信息：表名 `exp_problem_order`、中文名 `问题件处理单`、所属应用 `express_station_app`、开启「安全软删」。
2. **字段设计**：
   - `ticket_no` / `工单号` / `String` / **唯一、主显示**；点「高级」填编码规则 `EXP_PROBLEM`
   - `parcel_id` / `关联包裹` / `ManyToOne` / 目标数据表填 `exp_parcel` / **必填**
   - `urgency` / `紧急程度` / `Dict` / 下拉选 `SYS_URGENCY`
   - `issue_desc` / `异常描述` / `Text` / **必填**
   - `handle_result` / `处理结论` / `Dict` / 下拉选 `SYS_QUALITY_RESULT`
   - `evidence_file` / `破损拍照凭证` / `File`
   - `status` / `处理状态` / `Selection` / 填 `OPEN:待处理,PROCESSING:核查中,CLOSED:已办结`
3. **业务操作按钮**：
   - `startHandle`（`受理核查`）：`OPEN` → `PROCESSING`
   - `closeTicket`（`确认办结`）：`PROCESSING` → `CLOSED`
4. 点 **「检查影响并立即启用」** → 点 **「生成页面」**。

## 五、可视化布局与菜单编排（「页面与菜单编排」）

### 5.1 精简「包裹入库与取件」列表展示列

1. 进入 **「页面与菜单编排」**，在上半部分「页面列表布局配置」找到 **`exp_parcel_grid`** → 点 **「可视化设计」**。
2. 在可视化表格中取消勾选无需列表平铺的次要字段（如 `货架理货员`、`备注说明`、`快件规格`），仅保留：
   `入库流水号`、`快递运单号`、`快递品牌`、`收件人姓名`、`收件人手机`、`取件码`、`存放货架`、`滞留天数`、`超期保管费(元)`、`包裹状态`，并适当微调列宽后点击 **「保存页面布局」**。

### 5.2 梳理侧边栏菜单顺序并隐藏纯子表入口

1. 在下半部分 **「导航菜单目录」** 依次编辑各菜单排序号（`sequence`）：
   - `货架区位档案`：`10`
   - `快递车批次签收`：`20`
   - `包裹入库与取件`：`30`
   - `问题件处理单`：`40`
2. 找到底层子表菜单 **`随车包裹明细`**，点击「编辑」将 **「启用」开关关闭**（使其仅作为主表内的子表页签展示，不再单独占用左侧一级导航栏）。

## 七、快速复用指南：一键导入导出配置包

若在全新的空库上快速搭建同样的结构，只需两步即可复用：
1. 按第二节建好字典 `EXP_COMPANY`、`EXP_PARCEL_SIZE` 与编号规则 `EXP_INBOUND`、`EXP_BATCH`、`EXP_PROBLEM`（平台自带 4 组 `SYS_*` 字典已随库自动初始化）。
2. 进入「应用管理」点右上角 **「导入 / 导出配置包」**，打开「导入后立即上线可用」开关，贴入随附配置包 [express-station-package.json](file:///d:/MES/docs/express-station-package.json) 的 JSON 内容并点击 **「校验并导入」**，即可瞬间生成全部 5 张数据表、页面视图与导航菜单。
